## 一、简历项目描述（主推版）

### 项目名称
**Notebook-Evo · AI 知识工作台**（GitHub 开源，Public）

### 一句话定位
隐私优先、多模型、可自托管的 AI 知识工作台——管理研究资料，用 RAG 问答、混合检索、图谱推理与内容生产构建个人知识工作流。

### 项目描述（200 字左右，适合简历正文）

独立完成一款基于开源 Open Notebook 深度增强的 AI 知识工作台（5000+ 行 Python/TypeScript），涵盖 RAG 问答、多模型接入、内容生成与多端部署。核心成果：

1. **混合检索系统**：实现 BM25 全文 + 向量语义双路召回，RRF 融合 + Cross-Encoder 重排序，回答质量显著优于纯向量检索
2. **RAG 评估中心**：基于 RAGAS 实现忠实度/相关性/精确度/召回率四维自动评估，内置测试集 + 可视化报告
3. **多智能体编排**：设计 Agent 持久化层（跨重启恢复）+ 任务依赖 DAG 可视化编排，4 种 Agent 并行执行
4. **GraphRAG 图谱问答**：实体关系抽取 + 图谱路径推理与向量检索融合
5. **MCP Server**：将知识库能力暴露为标准 MCP 工具，AI 客户端可编程操作
6. **工程化**：40+ 单元测试、CI/CD、Docker 一键部署、14 语言 UI、Windows EXE + Android APK 多端

**技术栈**：Python · FastAPI · Next.js/React · SurrealDB（向量+图谱+文档一体）· LangGraph · Esperanto（20+ 模型商抽象）· RAGAS · FastMCP

**项目地址**：github.com/SCurrya/notebook-evo

### 项目亮点（面试口述版，3 分钟）

面试官，我主导增强了一个 NotebookLM 类的开源项目，把它做成了完整可展示的 AI 知识工作台。有三个技术亮点：

- **混合检索**：很多 RAG 项目只做向量检索，我实现了 BM25+向量双路召回，用 RRF 做无监督融合，再可选接 Cross-Encoder 重排。没有重排模型时自动降级，保证系统始终可用。这个设计是生产级 RAG 的标准范式。
- **RAG 评估**：我用 RAGAS 框架做四维自动评估，而不是靠人肉看回答质量。内置测试集一键跑分，还能导出报告。这体现了"用工程方法量化 AI 质量"的思维。
- **Agent 持久化 + MCP**：多智能体状态跨重启恢复，并把知识库能力通过 MCP 协议暴露出去，任何 AI 客户端都能操作它。MCP 是 2026 年 AI 工程最核心的协议之一。

## 三、面试问答准备（高频问题）

### Q1：这个项目你做了什么？哪些是你原创的？
诚实回答：项目基于 MIT 开源项目 Open Notebook。我的工作分三块：
1. **增强功能**：混合检索、RAG 评估、Agent 持久化、GraphRAG、MCP Server（上游没有的）
2. **产品化**：中文全 UI、一键演示、Docker 部署、文档体系
3. **工程化**：40+ 测试、CI、架构文档、安全清理（移除敏感文件）

### Q2：为什么用 SurrealDB 不用 PostgreSQL + pgvector？
SurrealDB 原生支持文档+向量+图三种模型，一个库搞定，不用维护多个数据库。对于这个体量的项目是合理选型。

### Q3：混合检索怎么做的？为什么效果好？
双路召回（向量抓语义、BM25 抓关键词）→ RRF 融合（无监督、无需训练）→ 可选 Rerank。关键是有 Rerank 时用，没有时降级 RRF，保证稳定。

### Q4：RAG 评估用 RAGAS 有局限吗？
有。RAGAS 依赖 LLM 打分，成本高且模型偏见。我做了启发式降级（关键词重叠），无 LLM 时也能跑。生产环境会配合人工抽检。

### Q5：多智能体为什么要持久化？
进程重启任务全丢。我做了 JSON 原子持久化 + BUSY→IDLE 恢复策略，保证任务不丢、状态一致。

### Q6：MCP 是什么？你怎么实现的？
MCP 是让 AI 应用调用外部工具的开放协议。我用 FastMCP 把知识库的检索/问答能力暴露成工具，AI 客户端就能"操作"我的知识库，而不是只看文字。
