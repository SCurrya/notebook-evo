# 测试与验收方案

本文档定义了本项目的三层测试体系、Agent 自动验证流程与用户验收边界，
确保每个功能模块在交付时质量可控、可验证。

## 三层测试体系

| 层 | 工具 | 内容 | 触发时机 |
|----|------|------|---------|
| 单元测试 | pytest / vitest | 服务层、工具函数、检索逻辑 | CI + Agent 自测 |
| 集成测试 | pytest + httpx | API 端点、数据库、图执行 | Agent 自测 |
| E2E 验收 | 脚本 + 手动 | 全链路（上传→检索→问答→评估） | Agent 预跑 + 用户复核 |

## Agent 自动验证清单（每功能交付时必过）

每个功能模块完成后，AI Agent 必须运行以下 6 项检查并输出报告：

```
[模块名] Agent 自验报告
1. 单元测试:  全部通过 (N tests) / 失败列表
2. API 冒烟:  POST/GET 各端点返回 200 / 异常记录
3. 数据验证:  数据库记录正确 / 无脏数据残留
4. 回归检查:  既有测试未被破坏 (N tests)
5. 边界检查:  空输入 / 超大输入 / 并发 处理正确
6. 日志检查:  无 ERROR 级日志泄漏
结论: PASS / FAIL (附原因与修复记录)
```

## 用户验收单（每个功能，用户只需打勾）

```
验收单 - [功能名]
□ 我能用 5 分钟内在本地跑起来看到这个功能
□ 功能行为符合设计文档描述
□ 界面是中文且无报错
□ 数据操作正确（增删改查无异常）
□ Agent 自验报告已附上且 PASS
□ 如发现问题: 描述 → 返回 Agent 修复 → 复验
```

## 验收边界（明确"什么不算缺陷"）

| 边界 | 说明 |
|------|------|
| 模型质量波动 | LLM 输出非确定性，允许语义等价的不同措辞；不接受事实错误 |
| 外部服务 | MoneyPrinterTurbo / 播客 TTS 需要外部服务，未启动时显示明确提示而非崩溃 |
| 性能 | 交互响应 < 10s 即可；不做基准测试（除非专项） |
| 兼容 | 仅保证 Chrome / Edge 最新版 + Android 12+ |
| 数据安全 | `.env` 永不入库；演示数据不含真实 API Key |
| 网络依赖 | 无外网时：演示 seed 支持 `--no-embed` 降级 |

## 验收流程

```
功能开发完成
  → [Agent] 运行单元测试 + 回归 → PASS?
      ├─ FAIL → 修复 → 重跑
      └─ PASS ↓
  → [Agent] API 冒烟 + 数据验证 → PASS?
      ├─ FAIL → 修复 → 重跑
      └─ PASS ↓
  → [Agent] 输出自验报告
  → [用户] 复核验收单（打勾）
      ├─ 问题 → 返回 Agent 修复 → 复验
      └─ 通过 → 标记功能完成
```
